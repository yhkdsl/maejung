# 마중 시연 영상 촬영 대본

**150초(2분 30초) 촬영 대본 완료. 2026-11-08 D1 실제 차·폰 시연 검증 완료, 영상 녹화·편집은 사용자 작업으로 남아 있다.** 준비·페어링은 영상 시간에 포함하지 않는다. 150초는 편집 목표이며 수동 확인을 포함한 스크립트 전체 실행시간과 다르다.

기준은 [TASKS.md 5절](TASKS.md#5-통합과-제출)과 기획서 4절의 “수요일 밤 10시, 대치동 학원가”다. 민지와 엄마의 하원 장면을 실제 차·폰 앱으로 재현한다. 수요일 22:00는 이야기 설정이며 호스트의 현재 날짜·시간을 맞추는 절차는 없다. 화면에는 **“에뮬레이터 시연 · GPS 이동 주입”**을 표시한다. 실제 도보·실차 촬영으로 설명하지 않는다.

## 1. 촬영 전 준비 — 150초 밖

- P4 커밋 `3c0b427`과 차의 좌표 겹침 지도 수정 `d5bdcc5`가 포함된 debug APK를 사용한다. 이번 실행 기준 HEAD는 `d5bdcc5`다. 실제 서버를 켜 두고 양쪽 APK가 같은 서버를 사용하도록 준비한다. 설치·페어링은 본편 밖에서 마친다.
- 폰은 `emulator-5556`, 차는 `emulator-5554`다. 이번 검증 때 두 기기는 이미 실행 중이어서 재사용했다. 새로 시작할 때는 [CLAUDE.md](../CLAUDE.md)의 "에뮬레이터 실행"을 따른다. 폰은 debug 미리보기가 아닌 실제 연결 화면, 차는 실제 서버 모드로 둔다. `fake-rider`는 사용하지 않는다. 서버 health와 두 serial의 연결 상태는 D1 실행 전 확인한다.
- 차 위치는 **위도 37.49950·경도 127.06030**, 폰 출발점은 **위도 37.49830·경도 127.06280**이다. GPS 주입 인자는 **경도·위도 순서**다. 현재 출발 거리 표시는 폰 **약 258m**(차 약 257m)이며 기획서의 120m는 예시다. 캡처에는 실제 수신·표시값을 그대로 쓴다.
- 이번 검증은 폰에 보존된 **MinjiP3** 테스트 계정을 재페어링·초기화 없이 사용했다. 차 홈에는 **“민지, MinjiP3”**가 보이며 민지는 한 번만 등록돼 있다. 이야기 속 인물은 민지다. 촬영 화면의 이름까지 맞추려면 별도 촬영 준비에서 민지 계정 연결을 조율하되 중복 등록을 피한다. 연결 코드·토큰·이름 입력 과정은 본편에서 제외한다.
- 폰의 정확한 위치·알림 권한을 허용하고 화면을 켜 둔다. 남은 요청·Sharing을 정상 종료해 양쪽 홈에서 시작한다. 수신 ETA가 아직 없거나 정지 course가 없으면 `—`를 그대로 두며 값을 채워 넣지 않는다.
- 차 Virtual Console에서 **기어 P·RR 닫힘**으로 준비한다. 이번 촬영의 실내등 원래 상태를 **OFF**로 확인·기록한다. Console에 실내등을 눈으로 확인할 표시가 없으므로 ON·원래 상태 복구의 근거는 **CarSession 로그**로 확보한다.
- 차·폰 앱 화면, Virtual Console, CarSession 로그의 캡처 위치를 준비한다. 운영용 Console·로그는 필요한 장면에만 삽입하고 지도 출처 문구와 폰 하단 종료 영역을 가리지 않는다.

## 3. 실행·캡처 체크리스트

### 실행

저장소 루트의 대화형 터미널에서 실행한다.

```bash
scripts/demo.sh --car emulator-5554 --phone emulator-5556 --car-user 10
```

로컬 서버 기본 주소는 `http://127.0.0.1:8080`이다. 위치 인자는 `[CAR [PHONE [SERVER]]]`, 환경변수는 `CAR_SERIAL`·`PHONE_SERIAL`·`SERVER_URL`·`ADB`·`CAR_USER`를 지원한다. 옵션은 `--car`·`--phone`·`--server-url`·`--adb`·`--car-user`·`--help`다. 차 Android 사용자는 **10**이며 `--car-user 10`처럼 옵션과 값을 띄어 쓴다. 기본 adb는 `~/Library/Android/sdk/platform-tools/adb`다. 서버 옵션은 health 확인 주소이며 설치 APK의 통신 주소를 바꾸지 않는다.

사전 점검 뒤 **9번의 Enter 확인**을 순서대로 진행한다. 각 단계의 실제 화면·로그를 확인한 뒤에만 Enter를 누른다.

1. Virtual Console의 **기어 P**와 CarSession 로그의 **실내등 원래 상태** 확인. 이번 테이크는 원래 OFF를 기록한다.
2. 양쪽 앱 **실제 서버 모드·페어링** 확인. 이번 검증은 기존 `MinjiP3` 계정을 재사용했다.
3. 폰 **데리러 와줘·정확한 위치 권한** 확인.
4. 차 **수락 버튼·양쪽 Sharing** 확인.
5. **새 학원 출발점 fix** 수신과 실제 거리 표시 확인. 이어지는 15등분·3초 간격 이동 45초 전체를 촬영한다.
6. **Nearby·실내등 ON**, 폰의 **“실내등을 켰어요”**·**“실내등 켜진 차를 찾아주세요”** 확인.
7. **30m 미만·P·Nearby**에서 Virtual Console **RR 열림** 확인.
8. 같은 **RR 닫힘** 확인.
9. **양쪽 탑승 종료·실내등 원래 상태 복구** 확인.

Enter 입력만으로 앱 동작 성공을 판단하지 않는다. 화면·로그가 기대와 다르거나 입력이 중단되면 해당 단계를 확인하고 재현 조건을 기록한다. 서버가 없으면 스크립트가 실행 방법을 안내하고 기기 조작 전에 종료한다.

### 캡처

- 요청 전 홈 → 폰 요청 대기 → 차 요청·버튼 수락 → 출발점 양쪽 Sharing → 45초 이동 → Nearby·**“실내등을 켰어요”**·**“실내등 켜진 차를 찾아주세요”** → RR 열림/닫힘 → 양쪽 탑승 종료·홈 순서를 확보한다.
- 시작 OFF·근접 ON 제어·종료 후 OFF 복구는 **CarSession 로그**, 탑승 종료는 `Send(SessionBoarded)`·`SessionEnded`와 양쪽 종료 화면으로 확인한다. Console의 RR 조작 화면과 실내등 상태의 증거를 구분한다.
- 양쪽 종료 안내는 약 3초 뒤 홈으로 돌아가므로 연속 화면 기록에서 해당 순간을 확보한다. 최종 홈·위치 공유 서비스 없음도 별도 확인한다. 차·폰 좌표가 겹치는 마지막 지도 화면도 최신 수정 기준으로 확인한다.
- 지도 출처·실제 HUD를 유지하고 코드·토큰은 노출하지 않는다. 아래 파일은 검증용 정지 화면이며 제출 영상은 별도로 촬영·편집한다.

실내등 ON의 근거는 앱의 ON 제어 효과와 양쪽 실제 안내이며 Nearby 도중 별도 SDK 스위치 조회를 실행한 것은 아니다. 시작과 종료 후 OFF는 SDK 조회 로그로 확인했다. Console에는 실내등 상태가 표시되지 않는다.

`bash -n`·`--help`가 통과했다. 서버 미실행·동일 serial·비대화형 stdin·없는 serial은 예상대로 종료 코드 1로 중단했고, 첫 수동 단계에서 Ctrl-C는 130으로 중단했다. 앱 상태 자동 검증과 사람의 화면 확인을 구분한다.

S4는 `docker build -t maejung-server server` 성공 후 별도 `127.0.0.1:18080` 컨테이너의 `/health`가 `{"status":"ok"}`임을 확인했다. 검증용 컨테이너만 중지·제거했으며 기존 8080 서버와 에뮬레이터는 유지했다. 이미지 `maejung-server`는 남아 있다. Railway 배포 검증은 포함하지 않는다.
